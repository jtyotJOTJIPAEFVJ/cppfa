## 2. How the optimizer works (as built)

`Search::run()` in `Optimizer.cpp`:

1. **setup**: modules in searched racks (default mid+low+rig) become open; everything else is pinned (`base_`). Slot counts from the engine's modified `medSlots`/`lowSlots`/`rigSlots`. With `Options::partial` (requests), only the flagged modules and requested empty slots are open; a rack's open count is its requested slots, at most its free slots (rack size minus the rack's pinned modules) and `maxSlots`. Module rules: a pinned module's state goes through `clampPinnedState` (also in the start fit; `Result::clamped` lists them).
2. **gatherCandidates**: every published module for each searched rack, filtered by canFitShipGroup/Type, capital size, rig size, officer (metaGroup 5), module rules (`excludedFromSearch`: assault damage controls), price cap, maxGroupFitted/maxTypeFitted vs pinned, `Engine::reach`, and the shield-active skip list (Capacitor Power Relay). Modules that need a charge (ASB, AAR, cap booster) get one candidate per valid charge.
3. **measure**: each candidate alone on the pinned fit (chunked one-slot SearchPlans): goal gain, divider drop, hp gain, capacitor budget gain, output gains, own fitting, unconstrained repair (`rep`), resonances changed (`resMask`) and ship fields changed (`shipChanged`). The best charge per charge-needing module is kept.
4. **interactions**: provisional subgroups (rack, group or rig family + calibration cost, resMask, size token from the name), representative = directly strongest. Rigs are split by calibration cost (T1 and T2 of a family are separate subgroups): with only the dearer T2 representative, stage 1 missed sets where only the T1 rig fits (Incursus case 6 with one rig slot open: a Small Processor Overclocking Unit I fixes CPU, the II doesn't fit calibration). `OPT_NO_RIG_CAL_SPLIT=1` restores one subgroup per family. One SearchPlan with all representatives gives each subgroup's influence. Pair gains (amplifiers, rigs that modify repairers or costs) are measured for every member of an influencing subgroup against each influenced representative.
5. **classify**: useless members drop. Roles per subgroup:
   - **resist**: changes only resonances alone, no pinned writes, and only influences other resist subgroups (fixed point; the RAH adapts to everything)
   - **fitting**: changes only outputs, influences nothing, uses no capacitor
   - **core**: everything else (all rigs are core)

   Members are sorted by a role-specific strength tuple, ties to the cheaper one (rigs: dearer).
6. **buildKinds / buildCorePlan**: one kind per subgroup (its representative). The core plan has every core kind in every slot of its rack, with influence enabled. It yields each kind's influencers (`inflKind_`), pinned influencers, and the kinds that change capacitor (`inflCap_`), HP (`inflHp_`), resists (`eps_`) and outputs (`inflFit_`).
7. **Records (the separable model)**: per-module `ModuleStats` keyed by the counts of only its influencers, plus cap peak and HP keyed the same way. Each is computed once with a core-plan evaluation and cached (`Cache<V>`, see 10.). `assemble(counts)` builds a core's module list and its `RepProfile`, so V(core, x) = `profile.repair(layer, x)` uses the engine's own code. The capacitor budget record (`budgetRecord`, used by the partial bounds) is composed from the module and cap-peak records the same way, without an engine call of its own (it used to be one engine call per capacitor projection: 1.7M on the Myrmidon). Fitting records per (output-influencer key, fitting set); `fitSlack` is cached per (output-influencer key, free slots).
8. **Resist tables (lazy, Phase A)**: one `ResistTable` per `eps_` key (the counts of the core kinds that change resists).
   - **Bounds** (`resistBounds`): the engine reports how it composed the layer's four resonances (`TestDetail::resonanceParts`). One test with only the eps modules gives the base value, preIncrease, unpenalized multiplier, postIncrease and the penalized multipliers with their penalty groups. One test per resist kind (eps modules + that kind) gives the kind's own multipliers: the list difference. Every resist set's D then follows pyfa's formula (sorted per penalty group and direction, `1 + (m-1)·exp(-i²/7.1289)`). It is computed in double during one depth-first walk over the rack multisets (each extends a prefix of the previous one; subtrees that don't fit next to the eps modules are skipped) and padded by 1e-5 to a lower bound.
   - **RAH**: the reactive hardener (the only resist kind other resist kinds influence) adapts. Its four resonances are some split of its total resist T (the adaptation conserves T, each type within [1-T, 1]). Each resonance, and so D, is concave in its multiplier, so D's minimum over that set is at a vertex: all of T on one damage type. The bound is the min over the four vertices.
   - Anything else (forced values, preIncrease/postIncrease changes, an eps multiplier that disappears, single-kind reconstruction off by > 1e-6, another adaptive kind, > 8 multipliers per kind and type) makes `resistBounds` fail. That table is then evaluated in full (the old path; `OPT_NO_ANALYTIC=1` forces it). No table has needed it so far.
   - **Exact records** (`resistRec`): a set's exact D, capacitor use and costs come from the resist plan (one engine call) when it is first needed, and are stored in lock-free chunks.
   - **Orders** (`ResistOrder`, per (eps key, free slots)): the table's sets grouped by rack size vector, each group sorted by bound (stable radix sort). `resistAt(order, i)` materializes the order on demand by merging the groups that fit and evaluating each set as its bound comes up. An evaluated set is emitted once its exact D is below every pending and in-flight bound. The result equals sorting all sets by exact D (stable, ties by set index), so stage 1 sees exactly what the old eager tables gave. Threads that need the same order evaluate its pending sets concurrently (`stepOrder`).
   - Every exact evaluation checks D >= bound and counts violations (log line "resist tables: ... bound violations"; a warning in `Result::warnings` if > 0). With `OPT_RESIST_VERIFY=1` (or `bruteForce`) every set is evaluated at build and checked.
9. **stage1**: best-first branch and bound, fixing one rack per level. Order: the rack holding the goal's own modules, then rigs, then the rest; that was 50x fewer cores than rigs first on the Incursus.
   - **Partial node bound** (`partialBound`): every split of each free rack's slots between value and resist side. Value side: HP or the capacitor budget, maximized per projection size; repairer items at their best stats over all influencer projections; min of the capacitor, slot, CPU and power knapsack relaxations. Resist side: min D over eps projections.
   - **Fitting prefilters**: `partialFits` (fixed modules at cheapest vs the most reachable output); **`fixedFits` (Phase A)**: when no kind in the free racks changes outputs or the fixed modules' costs, the fixed modules' measured costs (`assemble`) must fit within `fitSlack` of the free slots. That is the same test `feasibleMinD` applies to whole cores, and it holds for every completion, since added modules only cost more and leave fewer free slots. It cut the Myrmidon's bounded cores from 21M to 30k: its level-2 nodes (lows + rigs fixed) were often unfittable whatever the mids. Then `fitSlack` and `feasibleMinD` (core bound uses the best D among resist sets that leave room to fit).
   - **Core scan**: resist sets by D; score = V(core, x(R)) / D(R); fitting check with fitting-module sets; top-K heap (K = 200).
   - **Batches (Phase A)**: the top of the queue is processed in batches of fixed size: up to 64 partial nodes or 4,096 children (up to the next whole core), or up to 32 whole cores. Children's bounds and core scans run on the thread pool. Scans run against the cutoff at batch start plus their own finds, then merge into the top-K in queue order with the live cutoff, which keeps exactly what a sequential scan would. Batch sizes are constants, so results don't depend on the thread count. They can differ from a strictly one-node-at-a-time search only in ties at the K-th score; the 7 test cases are byte-identical to before Phase A.
10. **stage2**: per stage-1 set in score order, one SearchPlan with each slot's subgroup members as options. Exact local search: single swaps, then pair swaps; key (valid, fits, goal bucket, -price), where the goal bucket is `floor(log(goal) * 1e7)` (goals <= 0 or NaN share the lowest bucket), so goals within ~1e-7 relative compare by price. That key is a strict weak order, so every accepted move strictly improves it and the search ends; a cap of 10,000 accepted moves per starting set is a backstop that adds a warning (never hit). (It used to compare goals with a 1e-7 tolerance, which isn't transitive: the Incursus request `opt_parity/hang.json` cycled A -> cheaper B -> cheaper C -> A forever, C being just over 1e-7 below A.) Only fitting sets are reported; the final order is a stable sort. Memo by sorted candidate ids. Stops after `patience` (50) starting sets without improving the best fitting set. Starts run 16 at a time in parallel; each sees the memo of the earlier batches plus its own, and the patience rule is applied afterwards in start order (deterministic). Also records the max relative error of the model vs the exact score of each starting set: **0 on every test so far**.
10a. **refine** (after stage 2; see **`OPTIMIZER_STUDY.md`** for the study behind it). Stage 1 sees one representative per subgroup and stage 2 swaps members only within a slot's subgroup, so a weaker, cheaper-to-fit member (a compact damage control, 'Posse' hardeners, Syndicate plates), a different charge or a trade across subgroups was never tried. Refine searches every module choice of each open rack:
    - **Choices** (`buildPool`): every useful member of every subgroup (any role) plus the non-best charges of charge-using modules (`measure()` keeps them aside in `chargeAlts_`; candidate prices include the charge). Dominated choices are dropped: another choice of the same subgroup at least as strong in every measured effect (goal gain, divider drop, HP, capacitor, outputs, repair, pair and cost gains, pinned cost drops, own cap use) and at most as expensive in CPU, power, calibration and ISK, with no tighter `maxGroupFitted`/`maxTypeFitted`. That removes ~60-70 % (case 4: 758 -> 294 choices) and made refine ~4x faster with the same results (the member brute force below enumerates the unpruned list and found no loss). `OPT_NO_PRUNE=1` keeps all.
    - **Moves**, each screened with a SearchPlan built for it: one position (a fitted module or an empty slot) to any choice of its rack or empty (one plan per position over all choices, chunked); else pair moves: the one-move effects against the current set are added up, the `refinePairs` (256) pairs with the best estimated goal that are estimated to fit (0.5 % slack) are evaluated exactly (one plan per position pair). The best screened move is accepted if its **canonical** evaluation (`Engine::evaluate` of the pinned modules followed by the set in rack and candidate order, memoized per set) beats the current set by `better` (valid, fits, goal bucket, price): a strict weak order on sets, so the descent ends (`kStage2MaxMoves` backstop).
    - **Exact pass** (small requests): when the open slots have at most `refineExact` (3e7) combinations of the (pruned) choices and the enumeration needs at most 20k plans, every combination is evaluated exactly (`enumerate`, the same code as the member brute force) and its best fitting set becomes the first start. ~4.9 s at 16 threads / 43 s at 1 thread for 27M combinations (Hawk case 10 with 1 low, 2 mid, 1 rig open); 2-3 open slots are mostly well under 1 s. It found the only miss the iterated search left in the study (that set is 3-opt: no 2- or 3-position change improves it; the optimum changes all 4 slots).
    - **Phase 1**: steepest descent from stage 2's best distinct end sets (16; `refineStarts`), in parallel. If none fits (or stage 1's model hit a size limit, below), from the empty set.
    - **Phase 2**: iterated local search on 16 chains (`refineChains`, fixed so results don't depend on the thread count), started from the best phase-1 local optima. Each round perturbs every chain's set and descends again; a chain keeps the result if better. Perturbation: half the time a guided kick (one of the 32 strongest one-move neighbours by goal that didn't improve the set, i.e. mostly an upgrade that doesn't fit, which the descent then pays for with pair moves, plus 0-1 random changes), else 1-3 random positions to random choices. Seeds depend on (chain, round) only. It stops when `refinePatience` (800) chain iterations bring no better best set ("converged"), at the time budget (`timeBudget`, default 60 s for the whole run; "time"), or after `refineRounds` ("rounds"). Every local optimum found joins the end sets; the report takes the best fitting distinct ones (`report()`).
    - **Model limits**: a `ModelLimit` exception (too many kinds for a record key, the core plan, a projection key) used to fail the request ("too many influencing kinds for one record": 6 of 228 small sweep requests, e.g. case 1 with `low:2;mid:0;rig:0` open). Stages 1 and 2 are now skipped and refine searches alone from the empty set (`stats.modelSkipped`); on those requests it returns the member brute-force optimum in ~0.5 s.
    - Progress: `refine` at 0.80, then `refine: round N, best G` per round.
11. **Infeasibility** (`Result::infeasible`, response `status: "infeasible"`, see `OPTIMIZER_CLI.md`). An open slot may stay empty, so only the pinned part (the open slots empty) can make every choice unfittable. When it is over on CPU, power or calibration:
    - **calibration**, right after `setup()`: nothing raises calibration output or lowers a rig's calibration cost, and open rig slots only add rigs. Pinned calibration > output ends the run at once (no candidates, ~5 ms). The message names the pinned rigs whose removal alone fixes it (else all pinned rigs) and tells the user to select or remove one. Stage 1's cost bounds no longer scale calibration by `costScale_`, and `outputMax_[calibration]` is the base output.
    - **outputs**, after `measure()` (before the model): per open slot the strongest allowed output gain, compounded as a multiplier, and separately the largest drop of the pinned modules' needs (`Candidate::pinnedDrop`), added up. If the pinned need minus the drops is still above the raised output (pad 1e-6 relative + 0.01), no set fits. A necessary condition: it never rejects a fittable case (the sweep checks this against brute force).
    - **search**: otherwise stage 1/2 and refine run (refine from the empty set when stage 2 found no fitting set, over every member); if no fitting set is found and no fitting-module fill alone makes the pinned part fit, the reason is "search", with the bounds above in the message.
    - If some choice fits but none has a goal above 0, the status stays `ok` with no options and a warning ("no choice for the selected slots that fits gives a goal above 0 (free ...)").
    - With `bruteForce` (`--check`) the fast exits are skipped, so the brute force can confirm the diagnosis (feasible = 0); the response still has the infeasible status.
12. **Threads and caches** (refine: rounds are synchronous over a fixed 16 chains with seeds per chain and round, so its result is independent of the thread count unless the time budget stops it; `stats.refineStop` says which): `Pool` (fixed workers, `run(n, grain, fn)`; the caller is worker 0; not reentrant, so nothing inside a parallel loop starts another). `Cache<V>`: sharded open addressing over atomic node pointers. Lookups take no lock; a key is computed once (`std::call_once` per entry; other threads wait), so values are pure functions of their key and results don't depend on timing. Resist records and orders have their own lock-free publication (see 8.). The engine-call counter is atomic; stats like `engineCalls` / resist evaluations can vary slightly between runs (two orders of one table may evaluate the same set), results don't.

### Brute-force validation (`Options::bruteForce`, `--optimize-check`)
After stage 1, `Search::bruteForce()` enumerates every combination of the stage-1 kinds:
- per rack, every multiset of core + resist representatives within the slot count, kind caps and group limits, empty slots included
- each evaluated exactly with one SearchPlan holding all kinds of each rack in every slot, in parallel
- if it doesn't fit, it gets the first fitting-module fill (fewest modules first) that fits, also exact; the goal must not change (`fittingGoalChanges`)

The feasible combinations (goal > 0) sorted by exact goal must equal stage 1's top-K model scores rank by rank (relative 1e-5), and stage 1 must keep min(K, feasible) sets. A set the bounds or prefilters lost shows as a lower score at some rank. Stage 2 is skipped. `Options::maxSlots` makes the cases small (the CLI default is 2/2/1; 3/3/2 is up to 77M combinations, ~30 s).

**Phase B, ADC rule**: the old Hawk results counted an assault damage control (FFR Enduring ADC) as active. Its active bonus lasts ~12 s, so ADCs are now excluded from the search (5 published types) and pinned ones are evaluated at most online. Both Hawk goals changed (numbers above, Phase B build); the other five cases did not use an ADC and are unchanged.

(Small differences in cores bounded where the count went up come from batched expansion: a batch may expand a node that a strictly sequential search would have pruned after a scan in between.)

Where the time goes now (16 threads):
- **Myrmidon, Cyclone**: partial bounds. Myrmidon has 850 level-1 nodes x 364 rig children, each with `partialFits` + `fixedFits` (an `assemble` and a `fitSlack`); level-1 `partialBound`s enumerate rig x mid capacitor projections. Cyclone computes 625k level-2 partial bounds (mid fixed; rigs and lows free). Single-threaded these are the 12 s / 6 s of stage 1.
- **Absolution**: core scans. 2.5M sets are scored and 270k resist sets evaluated exactly: the scans walk deep because V(core, 0)/D stays above the cutoff while V(core, x)/D, with the cap use of active hardeners, doesn't.
- **Abaddon**: resist tables. 1,260 eps keys (layered coatings/membranes in the fixed lows x resist rig projections), each needing a bound walk over up to 205k sets: 1.6 s bound + 0.3 s sort, thread time. Siblings need the same tables at once, so these builds partly serialize.
- **Stage 2** is 0.1-0.5 s with 16 threads (1.9-3.1 s single-threaded on the bigger cases).

## 4. Known issues / limits

- **Fixed: stage 2 never finished** on `opt_parity/hang.json` (Incursus, 171/168.75 CPU, its 3 lows open): a 3-cycle among fitting sets through the non-transitive goal tolerance (see 2., item 10). Now 0.13 s; `--check` on it: 3,102 combinations, 500 feasible, 0 mismatches, best 229.01 (the optimizer's option 1: Centum C-Type membrane + 2x Corpii A-Type Small Armor Repairer, 164/168.75 CPU).
- **Stage 1 sees subgroup representatives only.** Feasibility in stage 1 (and `--check`) is decided over representatives: if only a weaker member with a lower cost fits, stage 1 misses it, and the representative brute force misses it the same way. Refine (2., item 10a) now searches every member and charge after stage 2 and from the empty set when nothing fit, so the final answer is member-level; the member brute force (`--members`) found no miss on 197 small requests (`OPTIMIZER_STUDY.md`). An "infeasible (search)" answer is still not a proof (refine is a local search), only the "calibration" and "outputs" reasons are.
- **Rig split cost**: more rig kinds make stage 1 2-5x slower on the parity cases (16 threads: case 4 0.9 -> 3.2 s, case 7 1.3 -> 2.9 s, case 12 0.8 -> 2.6 s; 1 thread case 4 4.8 -> 22 s); 3 of 12 cases found better and cheaper sets. `OPT_NO_RIG_CAL_SPLIT=1` gives the old behaviour and the old results.
- The "outputs" bound treats CPU and power separately: two open lows that would need a co-processor *and* a power module pass the bound and are decided by the search ("search" reason).

- **Resist bounds rely on the composition model.** They are checked: every set used is evaluated exactly, every evaluation checks its bound (warning if violated), and `OPT_RESIST_VERIFY=1` checks all. Anything the model can't express falls back to exact tables (counted in the log as "evaluated in full"). The RAH vertex bound assumes pyfa's adaptation conserves the RAH's total resist, which it does for the uniform profile; revisit if non-uniform damage profiles are added.
- Stats (`engineCalls`, resist evaluations) can differ slightly between runs with threads: two orders of one table may evaluate the same set concurrently. Results are deterministic and independent of the thread count (batch sizes are constants).
- `Pool::run` must not be called from inside a parallel loop (not reentrant). Table builds triggered inside parallel loops run on one thread; siblings waiting for the same table idle (Abaddon).
- `OPT_RACK_ORDER`, `OPT_NO_FITPRUNE`, `OPT_NO_ANALYTIC` and `OPT_RESIST_VERIFY` env vars are debugging hooks.
- The size token comes from names (`'Micro' Cap Battery` gets no size). Harmless but splits a subgroup.
- `projections()` key (Phase B fix): it packed up to 15 kind indices into 128 bits and threw "too many free kinds in one projection" on a request with pinned modules (Myrmidon 2593, armorActive, 1 mid + 2 low + 1 rig open). It is now a bit set over the kinds (at most 125 kinds) plus the free-rack mask; results of all regression cases are unchanged.
- `packCounts` keys hold at most 32 kinds of 4-bit counts; not hit so far.
- Module rules are in `excludedFromSearch` / `clampPinnedState`; add similar rules there.
- Group limits shared across roles are checked per set; `maxTypeFitted` for variants only in stage 2.
- Prices come from pyfa's `prices` table; 0 or missing = no price (counts as over a price cap).

### Improvement study: refine - DONE
Full write-up: **[`OPTIMIZER_STUDY.md`](OPTIMIZER_STUDY.md)** (reference method, gaps, per-strategy results, final tables, next steps). In short:
- The old pipeline (stage 1 + 2) missed the exhaustive member-level optimum in 10-13 % of small requests (by 14 % on average, up to 35 %) and was below the best known set in 7 of 19 whole-rack cases (up to 14.9 %). The cause is mostly representative choice when fitting binds: the right answer uses weaker, cheaper-to-fit members, traded across subgroups.

### Phase C: pyfa UI (Python, wxPython) - DONE

**Use**: select one or more mid, low or rig slots in the fitting view (modules or empty slots; shift/ctrl-click), right-click, **Optimize Modules (N slots)...** (on a module it is in the module's part of the menu; on an empty slot in the ship's part). The window shows the slots; pick the goal, max price per module (million ISK, 0 = none), officer modules and the number of results, then **Run**. A gauge shows the exe's progress lines; **Cancel** kills the process. Results: one row per option (goal, gain, price, price change, CPU, PG, calibration, cap used / recharge, fits, the changed modules with counts); the first row ("now") is the fit as it was. Click a column header to sort (again to reverse). Selecting a row lists what goes into each slot below the table. **Double-click (or Enter) fits the option** as one undoable step (Ctrl+Z); the window stays open, so another option can be applied on top (it replaces the same slots), and the "now" row puts the original modules back. pyfa recalculates and shows its own numbers. Warnings from the response are shown above the table; for `clampedModules` (pinned assault damage controls set active) a **Set them online** button sets them online (also undoable). **Optimizer path...** chooses the exe; if the exe is missing, Run says so and offers to choose it.

Files:
- `service/moduleOptimizer.py` (no wx): `buildRequest(fit, positions, goal, ...)` writes the request from the Fit (ship, mode, character, `fit.appliedImplants`, boosters with active side effects, every `fit.modules` entry with position = list index, state, charge, mutations, `optimize` for the selected positions). Character: none for All 5 (all V), `defaultLevel 0` and no skills for All 0, otherwise `defaultLevel 0` plus every skill the character has above 0 (`char.getSkill(id).level`, which includes alpha clone caps). Prices: all rows of pyfa's `prices` table with price > 0 (~4.5k types) are always sent in `prices`, so the exe never opens saveddata. `parseResponse` -> `OptimizerResult` / `Option` / `SlotChoice` / `FitStats`. `OptimizerRun` runs `PyfaReader.exe --game <eve.db> --optimize-request - --out -` (request on stdin, response on stdout) with `CREATE_NO_WINDOW` on Windows, reads `progress` lines from stderr, cancel = kill, timeout (setting, default 300 s), error response / exit code / non-JSON output -> `OptimizerError` with the message. `fitMatchesRequest` checks that the pinned modules are unchanged before applying.
- `gui/moduleOptimizerDialog.py`: the window (`wx.Frame`, float on parent, one at a time). The run is a daemon thread; progress and results come back with `wx.CallAfter`. Unchanged slots of an option are applied from a `ModuleInfo` snapshot taken at Run time, so a mutated module that stays keeps its mutations even after another option was applied.
- `gui/fitCommands/gui/localModule/optimizerApply.py`: `GuiApplyOptimizedModulesCommand(fitID, {position: ModuleInfo or None})`: frees every changed slot first, then fills them (`CalcReplaceLocalModuleCommand`, restrictions checked), so group limits can't trip on the way; undo restores everything.

- `service/settings.py`: `ModuleOptimizerSettings` (`pyfaModuleOptimizerSettings`: `exePath` ('' = `<pyfa root>/cpp/bin/Release/PyfaReader.exe`), `goal`, `priceCap`, `allowOfficer`, `results`, `threads` (0 = all; no UI), `timeout`).

SQLite can't open a database inside the WSL file system from Windows (`\\wsl.localhost\...` gives "database is locked"), so when pyfa's eve.db isn't under `/mnt/`, `--game` is left out and the exe uses the eve.db it finds next to/above itself (the repo's `eve.db` for `cpp/bin/Release`).
